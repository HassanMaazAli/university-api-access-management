Security Note: Client-Side Key Storage Analysis

In this educational full-stack system, the active API key is stored strictly within browser sessionStorage.

  • Session Scoping: Credentials persist only for the current tab and are completely wiped when the browser tab is closed.
  • Protection Against URL Leakage: The key is never appended to URLs or query strings, avoiding exposure in browser history, proxy logs, or web analytics.
  • Header-Only Authentication: Every AJAX request explicitly attaches the key in the x-api-key HTTP header.
  • Storage Trade-offs: In a production zero-trust SaaS product, keys stored in browser storage are susceptible to malicious Cross-Site Scripting (XSS). An enterprise architecture would pair short-lived HttpOnly SameSite JWT cookies or backend OAuth proxy tokens with API keys reserved for server-to-server daemon requests.
